Ship-to country → store redirect

Use the location selector as a "Where should we ship to?" prompt that sends each visitor to the webstore serving their country.

The visitor types a country, the selector resolves it to an ISO code, the code is looked up in a store map, and the browser is sent to that store with the country in the URL so the destination can preselect it.

1. Live demo

Pick a country and watch the destination resolve on the right. "Go to store" runs a simulated redirect so you stay on this page. Tick the checkbox to open the real URL instead once you have replaced the placeholder store addresses.

Country codes, native names and nicknames all work (try "uk", "deutschland", "nz").

    3. How the redirect works

    1. Remembered choice first. If the visitor chose a store before and ticked "remember", that store is read from localStorage and they can be sent on immediately (the demo only preselects it, so you can see the state).
    2. Otherwise suggest from the browser. The region part of navigator.language (for example the GB in en-GB) preselects a likely country. The visitor can still change it, which matters because a browser language is a weak signal for where someone wants goods shipped.
    3. The selector resolves the country. The plugin writes the chosen option into the hidden select and fires change. The option's ISO code is the first token of its data-alternative-spellings, so no second lookup table is needed.
    4. Code → store. The store map is searched for the code. No match means the fallback store.
    5. Redirect with context. The visitor is sent to store URL + ?country=CODE. The destination store can read that parameter to preselect the shipping country, currency or market, so they do not have to choose twice.

    Production notes

    • Confirm rather than auto-redirect on first visit. Search engines and visitors on VPNs dislike silent redirects. Show the selector (or a banner suggesting the store) and redirect on an explicit choice, then remember it.
    • Give every store a way back. Each store should show the selector too, so a visitor sent to the wrong one can switch, and switching should overwrite the remembered choice.
    • Separate stores vs one store with markets. This pattern fits separate storefronts on different domains. If your stores are Shopify Markets inside one shop, submit Shopify's localization form with the chosen country instead of redirecting across domains.
    • Keep the selector and the map in sync. Every country in the selector should resolve somewhere, which the fallback store guarantees.

    4. The code that matters

    var STORES = {
  us:   { name: 'US store',   url: 'https://us.example.com/', countries: ['US', 'PR', 'GU'] },
  uk:   { name: 'UK store',   url: 'https://uk.example.com/', countries: ['GB', 'JE', 'GG', 'IM'] },
  eu:   { name: 'EU store',   url: 'https://eu.example.com/', countries: ['DE', 'FR', 'NL', ...] },
  intl: { name: 'International store', url: 'https://www.example.com/', fallback: true }
};

function storeForCode(code) {
  for (var key in STORES) {
    if ($.inArray(code, STORES[key].countries || []) >= 0) return STORES[key];
  }
  for (var key in STORES) { if (STORES[key].fallback) return STORES[key]; }
}

$('#shipto-country').selectToAutocomplete().on('change', function () {
  var $option = $(this).find('option:selected');
  var code = ($option.data('alternative-spellings') || '').split(' ')[0];
  var store = storeForCode(code);
  if (!store) return;
  var url = store.url + '?country=' + encodeURIComponent(code);
  try { localStorage.setItem('shipto', JSON.stringify({ code: code, url: url })); } catch (e) {}
  window.location.assign(url);
});
